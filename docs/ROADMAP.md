# SafeZone AI Mobile — Roadmap and Deliverables

Progress is tracked interactively in the HTML dashboard. Each phase must be accepted after actual tests.

## P00 — التأسيس وتثبيت القرارات
**Goal:** إعداد مشروع Flutter قابل للبناء وله هيكل واضح ومعايير قبول قبل إضافة أي ميزة.
**Dependencies:** None

### Tasks
- [ ] التحقق من flutter doctor وDart وJava وAndroid SDK وADB وإعداد جهاز Z Flip3 للتصحيح.
- [ ] إنشاء مشروع Flutter باسم safezone_mobile وبمعرّف com.safezone.ai.mobile دون لمس مشروع Windows.
- [ ] إنشاء المجلدات الأساسية للـfeatures وcore وapp وshared والاختبارات والتوثيق.
- [ ] تعريف Architecture Decision Records وواجهة تجريد للكاميرا والاستدلال ومستودع النماذج.
- [ ] كتابة ARCHITECTURE.md وMODEL_CONTRACT.md وROADMAP.md وTEST_PLAN.md وREADME عربي.
- [ ] تهيئة Git و.gitignore وإدارة الأسرار والإصدارات وخطة migrations.
- [ ] اجتياز flutter pub get وflutter analyze وflutter test (واختبار build debug إن توفرت الأدوات).

### Deliverables
- مشروع Flutter منظم
- docs/ARCHITECTURE.md
- docs/MODEL_CONTRACT.md
- docs/TEST_PLAN.md
- Git baseline + تقرير بيئة التطوير

**Acceptance:** كود مهيكل، flutter analyze بلا أخطاء، اختبارات التأسيس ناجحة، تقرير الأدوات حقيقي، ومراجعة الوثائق قبل كتابة الكاميرا.

## P01 — الكاميرا والواجهة الأولية
**Goal:** فتح كاميرا الهاتف بصورة مستقرة، مع شاشة عربية وإدارة دورة حياة التطبيق وطَيّ الهاتف.
**Dependencies:** p0

### Tasks
- [ ] بناء شاشة الرئيسية بالعربية RTL مع حالة تشغيل الكاميرا وأزرار البدء/الإيقاف.
- [ ] اختيار مالك واحد لجلسة الكاميرا وتجنب تشغيل camera plugin وYOLOView معاً على نفس الجلسة.
- [ ] طلب إذن CAMERA وقت الحاجة ومعالجة الرفض الدائم والكاميرا غير المتاحة.
- [ ] التبديل بين الأمامية والخلفية؛ إيقاف البث وتحرير الموارد عند الانتقال للخلفية.
- [ ] اختبار نسبة الأبعاد والدوران 0/90/180/270 وعدم عكس الصندوق لاحقاً.
- [ ] اختبار الشاشة مفتوحة ومطوية جزئياً ضمن ما يدعمه Android على Z Flip3.
- [ ] تشغيل التطبيق على الهاتف وفحص عدم حفظ الصور أو الفيديو أو الاتصال بالشبكة.

### Deliverables
- واجهة كاميرا عربية حقيقية
- تصحيح أبعاد واتجاه المعاينة
- إدارة الأذونات ودورة الحياة
- فيديو إثبات تشغيل قصير إن رغب المستخدم دون حفظ داخل التطبيق
- تقرير اختبار الجهاز

**Acceptance:** الكاميرتان تعملان على Z Flip3، لا تشوّه في الصورة، لا انهيار عند الطي/العودة، ولا حفظ تلقائي للوسائط.

## P02 — مكتبة النماذج والتبديل
**Goal:** ملف نموذج جديد يدخل إلى مكتبة التطبيق عبر منتقي ملفات Android ويصبح قابلاً للتفعيل بعد التحقق من التوافق.
**Dependencies:** p1

### Tasks
- [ ] إنشاء نموذج بيانات ModelEntry وModelProfile ومستودع models + app_settings مع migrations منظمة.
- [ ] استيراد ملف .tflite من Android Storage Access Framework إلى مجلد app-private، وحساب SHA-256.
- [ ] عرض اسم الملف وحجمه والفئات والمدخلات وحالة التحقق، وإدارة حذف/تكرار النماذج.
- [ ] تعريف manifest اختياري model.json، مع قراءة بيانات النموذج المدمجة عند توفرها ورفض التناقض.
- [ ] التحقق من Task=detect وشكل التنسورات والبنية المتوافقة، ثم إجراء smoke inference قبل تفعيل أي ملف.
- [ ] تجريب plugin switchModel() على مسار app-private حقيقي، وحفظ النموذج النشط بعد إعادة فتح التطبيق.
- [ ] تنفيذ rollback للنموذج السابق بعد فشل التفعيل مع رسالة واضحة وعدم إظهار نجاح زائف.
- [ ] اختبار نماذج صالحة/معطوبة/غير متوافقة/مكررة ودقة الاستمرار بعد إعادة التشغيل.

### Deliverables
- شاشة إدارة النماذج
- مستودع SQLite للنماذج والإعدادات
- استيراد ملف من الهاتف بلا صلاحية تخزين عامة
- تفعيل/استرجاع تلقائي عند الفشل
- اختبارات استيراد ومطابقة

**Acceptance:** استيراد نموذجين متوافقين والتبديل بينهما على هاتف حقيقي دون إعادة APK؛ يرفض الملف المعطوب ويستعيد النموذج السابق.

## P03 — دمج كشف الكمامة الحقيقي
**Goal:** إعادة استخدام best_mask_v4.pt عبر تحويل مختبر وتشغيل كشف ملتزم/مخالف/غير مؤكد على الهاتف.
**Dependencies:** p2

### Tasks
- [ ] حفظ نسخة من best_mask_v4.pt واستخراج names/imgsz/Ultralytics version في manifest.
- [ ] تصدير النموذج في Colab إلى LiteRT/TFLite بالطريقة المتوافقة مع إصدار YOLO11n والإضافة المختارة.
- [ ] التحقق من شكل دخل/خرج النموذج وlabels وpreprocessing وNMS قبل استيراده.
- [ ] مقارنة توقعات نسخة .tflite بنموذج .pt على عينة صور ثابتة لتحديد أثر التحويل.
- [ ] استيراد الملف من التطبيق وتفعيله، وربط الفئات الثلاث بقواعد السلامة.
- [ ] عرض مربعات الوجه/الثقة وحالة COMPLIANT / VIOLATION / REVIEW دون افتعال نتائج.
- [ ] اختبار كمامة صحيحة وغياب الكمامة وارتداء خاطئ وزوايا جانبية ووجه غير ظاهر.
- [ ] ضبط threshold بشكل تجريبي مع توثيق الحالات غير المؤكدة والمكررة.

### Deliverables
- نموذج .tflite + model.json
- تقرير parity بين .pt و.tflite
- كشف حي من كاميرا Z Flip3
- واجهة عرض حالة السلامة
- مصفوفة أخطاء أولية

**Acceptance:** النموذج الحقيقي يعمل دون لابتوب أو شبكة، وتتطابق الفئات والنتائج الأساسية على عينات الاختبار؛ حالات عدم اليقين تظهر REVIEW.

## P04 — قياس الأداء والتحسين
**Goal:** اختيار إعداد يحقق سلاسة عملية مستدامة، لا مجرد رقم FPS مرتفع في بداية التشغيل.
**Dependencies:** p3

### Tasks
- [ ] قياس input camera FPS وinference FPS وmedian/p95 latency وفصلها عن FPS المعاينة.
- [ ] إضافة أحدث إطار فقط مع backpressure وحد أقصى لطابور الاستدلال دون تكدس.
- [ ] مقارنة CPU وGPU عند توفرهما ورصد فشل delegate والعودة إلى CPU.
- [ ] تجريب دقة إدخال أقل/تصدير كمي متوافق إذا لزم، ومقارنة أثره على الدقة.
- [ ] اختبار استهلاك الذاكرة وحرارة الجهاز والبطارية خلال 10–15 دقيقة تشغيل.
- [ ] اختبار التحرك والاقتراب والبعد والإضاءة والوجه الجانبي على Z Flip3.
- [ ] حفظ تقرير benchmark قابل لإعادة الإنتاج مع إصدار النموذج والتطبيق والجهاز.

### Deliverables
- جدول قياسات CPU/GPU
- تقرير median/p95 inference latency
- ملف قرارات ضبط النموذج
- خط أساس للأداء والدقة

**Acceptance:** لا انهيار أو تزايد غير محدود في الذاكرة خلال الاختبار؛ النتائج والسرعات موثقة، ويُختار إعداد عملي وفق المعايير المتفق عليها.

## P05 — Gate Mode — وضع البوابة
**Goal:** ترجمة الخبرة السابقة في الفيديو إلى مرور مرصود مع تجنب التكرار والاعتراف بالوجه غير المرئي.
**Dependencies:** p4

### Tasks
- [ ] تعريف مخرجات passage episode مقابل tracked identity مقابل verified crossing بوضوح.
- [ ] تنفيذ تجميع الأدلة بحسب زمن الفيديو/الإطارات مع فصل المرور المتتابع وتجنب التكرار.
- [ ] تنفيذ confidence aggregation وحالة REVIEW عند عدم كفاية الأدلة.
- [ ] إضافة نطاق اهتمام ROI للباب واختبار تفعيل خط افتراضي فقط إذا توفرت أدلة تتبع مناسبة.
- [ ] اختبار متطوع واحد متكرر وعدة أشخاص وعودة نفس الشخص وحجب الوجه.
- [ ] قياس precision/recall للمرور الحقيقي وعدد الإيجابيات/السلبيات الخاطئة.
- [ ] توضيح القيود والتمييز بين عبور فعلي وظهور وجه؛ عدم ادعاء التعرف على الهوية.

### Deliverables
- GateModeProcessor مستقل
- نتائج المرور الموثقة
- تقرير false positives / false negatives
- واجهة تفعيل وضع البوابة

**Acceptance:** سيناريو الفيديو المرجعي (3 مرات: مخالفتان والتزام) ينجح على الموبايل، مع توثيق القيود واختبارات مرور إضافية قبل الادعاء بالاعتمادية.

## P06 — الإحصائيات والخصوصية والتصدير
**Goal:** عرض النتائج المباشرة دون خلطها بالتاريخ، مع خيارات حفظ بيانات أحداث مجهولة الهوية فقط.
**Dependencies:** p5

### Tasks
- [ ] تنفيذ إحصاء مباشر داخل الذاكرة: COMPLIANT وVIOLATION وREVIEW، مع تمييز الفريمات عن مرات المرور.
- [ ] إضافة خيار حفظ سجل الأحداث metadata معطلاً افتراضياً وبموافقة صريحة.
- [ ] إنشاء SQLite monitoring_sessions وdetection_events عند تفعيل السجل فقط.
- [ ] إظهار نموذج مصدر البيانات النشط ووقت بدء الجلسة وعدم إخفاء القاعدة المستخدمة.
- [ ] تنفيذ بدء جلسة جديدة دون حذف تاريخ قديم إلا بأمر منفصل واضح.
- [ ] تصدير CSV للبيانات غير الشخصية المختارة، وتحديد الاحتفاظ والحذف التلقائي.
- [ ] التحقق من عدم وجود صور أو إطارات أو معرّفات أشخاص في السجل.

### Deliverables
- لوحة إحصائيات داخل الهاتف
- تخزين أحداث اختياري فقط
- CSV للأحداث
- سياسة خصوصية وحذف واضحة

**Acceptance:** الأرقام متسقة مع مصدر واحد، ويمكن بدء جلسة دون فقدان السجلات القديمة، والتسجيل مغلق افتراضياً، وCSV لا يحتوي صوراً.
